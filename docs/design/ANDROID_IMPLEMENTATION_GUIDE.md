# Eluno: руководство и требования к реализации дизайна в Android

Дата: 31 октября 2026 года. Статус: спецификация для следующего этапа разработки; не отчёт о готовности нативного интерфейса.

## 1. Назначение и источники истины

Перенести выбранный пользователем вариант 2 в Kotlin / Jetpack Compose / Material 3, сохранив архитектуру локального Matter-контроллера. Android App Widgets реализовать отдельно через Jetpack Glance.

Порядок приоритетов при расхождении материалов:

1. Семантика данных, безопасность команд и границы модулей из [архитектуры](../ARCHITECTURE.md).
2. Требования этого документа к Android, доступности и адаптации.
3. Согласованная композиция из [описания дизайна](DESIGN.md) и работающего прототипа.
4. Растровые концепты как визуальные ориентиры, а не точные измерительные чертежи.

Материалы для реализации:

| Материал | Путь от корня проекта | Назначение |
| --- | --- | --- |
| Выбранный главный экран | `docs/design/concepts/02-device-grid.png` | Плитки, иерархия, лавандовая палитра |
| Остальные экраны | `docs/design/screens/` | Лампа, лента, добавление, настройки, Fold |
| Работающее поведение | `design-prototype/src/Prototype.tsx` | Сценарии демо и переходы |
| Визуальные значения | `design-prototype/src/prototype.css` | Отправная точка токенов |
| Виджеты | `design-prototype/public/widgets/index.html` | Три композиции и состояния |
| Финальные снимки | `design-prototype/qa/*-final.png` | Сравнение результата при одинаковом состоянии |
| Ограничения проверки | `design-prototype/design-qa.md` | Что проверено только в браузере |

**Обязательно** означает критерий приёмки. **Рекомендуется** означает предпочтительный способ реализации. Числа, обозначенные как стартовые, уточняются при измерении нативного экрана и документируются; они не являются нормами Android.

Не переносить рамку телефона, часы, камеру, системную клавиатуру, панель навигации и меню выбора устройства из браузерного просмотрщика. Их рисует ОС. Не использовать скриншоты как интерактивный интерфейс.

## 2. Область работ и текущее состояние

В проекте уже существуют Compose-экраны, ViewModel и domain-контракты; это перенос оформления и адаптации на существующую основу. В `:feature:widgets` пока есть контракты привязок, полноценного Glance-интерфейса нет. Реальный Matter-порт пока не реализован. Дизайн не должен скрывать эти ограничения.

- Сохранить разделение `demo` / `production`. Демоданные и действия сброса доступны только в demo.
- Не подменять production демонстрационным успешным подключением или выполнением команды.
- Первый этап: тема, карточки, экраны, адаптация и доступность в demo.
- Второй этап: Glance и привязки на общем устойчивом пути команд; реальные устройства проверяются после подключения Matter.
- Пресеты яркости/цвета на виджете, настоящий commissioning и новые возможности вне согласованного дизайна не входят автоматически в первый этап.

## 3. Размещение в архитектуре

| Область | Место реализации | Требование |
| --- | --- | --- |
| Тема и корневая навигация | `app/.../MainActivity.kt`, затем выделенные файлы темы | Не оставлять весь новый UI в Activity |
| Список и управление | `:feature:devices`, текущий `DevicesFeature.kt` | Выделить небольшие переиспользуемые компоненты |
| Добавление | `:feature:commissioning` | Разделить демокаталог и будущий реальный сценарий |
| Настройки | `:feature:settings` | Использовать существующий `SettingsRepository` |
| Виджеты | `:feature:widgets` | Свои Glance-компоненты, без зависимости от экранных ViewModel |
| Состояние и команды | `:core:domain`, `:core:data` | Использовать общий репозиторий; UI не обращается к DAO или Matter SDK |

Рекомендуемые компоненты: `DeviceTile`, `DeviceStateLabel`, `PowerAction`, `ConfirmedValue`, `CapabilityControls`, `EmptyDevices`, `DeviceErrorPanel`, `ElunoTheme`. Это предлагаемые имена, не описание уже существующих классов.

Общие UI-токены вынести в доступный feature-модулям UI-слой. Если вводится `:core:designsystem`, добавить его как отдельное архитектурное изменение; `:core:domain` не должен импортировать Compose или Android. В Glance переиспользуются ресурсы/значения и модель представления, а не обычные Compose-компоненты.

Зависимости Adaptive, WindowManager и Glance добавлять через version catalog с проверкой совместимости закреплённого стека. Не менять версии всего проекта только ради копирования примера документации.

## 4. Токены оформления

### Цвет

Ниже обязательная базовая светлая палитра при выключенных динамических цветах. Использовать смысловые роли темы вместо HEX в каждом компоненте.

| Роль Eluno | Значение | Использование |
| --- | --- | --- |
| Фон | `#FFFBFE` | Основная поверхность |
| Основной текст | `#211F26` | Названия, значения |
| Вторичный текст | `#686273` | Подписи, время подтверждения |
| Акцент | `#6750A4` | Основные действия |
| Активная поверхность | `#EADDFF` | Подтверждённое включённое устройство |

Сопоставить роли с `ColorScheme`: `surface`, `onSurface`, `onSurfaceVariant`, `primary`, `primaryContainer` и подходящими контрастными парными ролями. Дополнительные поверхности, границы и состояния задать централизованно. Не считать `primaryContainer` единственным сигналом включённого состояния.

Обязательно: светлая, тёмная и системная темы; выбор сохраняется существующим DataStore. На Android 12+ включённые динамические цвета используют системную палитру, на API 28–30 — базовую палитру. Зелёный пример браузера не переносить как «цвета обоев». Тёмную тему не получать инверсией изображения. Проверять контраст каждой пары текста и фона, включая disabled и ошибки. Проектная цель: 4,5:1 для обычного текста, 3:1 для крупного текста и существенных графических контролов.

### Типографика и геометрия

Стартовые значения для Compose; текст в `sp`, геометрия в `dp`. Они отражают дизайн Eluno, а не обязательные размеры Material-компонентов.

| Элемент | Стартовое значение |
| --- | --- |
| Заголовок экрана | 32–36 sp, bold, высота строки 38–44 sp |
| Название устройства в плитке | 16 sp, medium/bold, 20–22 sp |
| Крупное числовое значение | 32–40 sp, bold |
| Основной текст / действие | 14–16 sp |
| Дополнительная подпись | 12–14 sp, не уменьшать ради размещения |
| Поля экрана | 16–20 dp; допускается 14 dp в узкой сетке |
| Между карточками | 12 dp |
| Внутри карточки | 16 dp |
| Скругление карточек/панелей | 24 dp |
| Цель касания | Не меньше 48 × 48 dp |
| Обычная иконка действия | 24 dp внутри цели касания |

Использовать системный sans-serif с кириллицей; соответствие Roboto проверять на Android. Не встраивать растровый текст. Длинные названия допускают перенос; в карточке после двух строк возможен ellipsis, полное название доступно в деталях и TalkBack. На экране деталей текст переносится без потери названия. Высота карточек растёт с текстом, проценты и Kelvin не разрываются внутри значения.

Стандартные векторные пиктограммы одной семьи, одинаковая толщина линий. Цвет, состояние и тип устройства должны быть понятны без различения одной только иконки. Декоративным изображениям не задавать лишние описания.

## 5. Требования к экранам

| Экран | Обязательная композиция и поведение |
| --- | --- |
| Устройства | `eluno`, настройки, заголовок, демопометка только для demo, сетка, доступное добавление |
| Плитка | Тип/иконка, название, подтверждённое состояние, поддерживаемые показатели; отдельная кнопка питания |
| Лампа | Заголовок, питание, яркость и температура только при наличии соответствующих capabilities |
| Лента | Питание, яркость, переключение «Цвет / Температура» только для поддерживаемых режимов; выбранный цвет отмечен также галочкой |
| Розетка | Питание и состояние; не добавлять вымышленные энергопотребление и мощность |
| Добавление demo | Пять текущих шаблонов, ясное обозначение демонстрации, защита от повторного добавления |
| Настройки | Системная/светлая/тёмная темы, динамические цвета с учётом версии ОС, сведения о приложении, подтверждаемый демосброс |
| Переименование | Текущее имя, проверка непустого значения после trim, понятная ошибка, сохранение/отмена |
| Удаление | Название устройства и последствия до подтверждения; не смешивать удаление демозаписи с Matter unpairing |
| Пустой список | Короткое пояснение и действие добавления |
| Ошибка загрузки | Сообщение и повтор; не заменять ошибку пустым списком |

На плитке нажатие питания не должно одновременно открывать детали. Название/основная область открывает конкретный `DeviceId`. На compact переход заменяет экран, Back возвращает список. Добавление и настройки сохраняют понятный обратный путь. Не добавлять нижнюю навигацию только ради заполнения свободного пространства.

Диапазоны лампы 5–100% / 2700–6500 K и ленты 1–100% / 2200–6500 K относятся к текущим демошаблонам. Реальные пределы читать из capabilities, не определять по категории. Положение ползунка рассчитывать по диапазону: `(value − min) / (max − min)`; обработать вырожденный диапазон.

Ползунок меняет локальный черновик при движении; отправка по завершении жеста, без команды на каждый пиксель. До подтверждения явно отделять выбранное значение от подтверждённого. Обновление извне не должно незаметно перетягивать ползунок под пальцем. После завершения конфликта отображать фактический результат общего репозитория.

Системные компоненты для dialog/sheet/выбора цвета предпочтительнее копирования HTML. На маленькой высоте содержимое прокручивается, действия остаются достижимыми над IME. Нельзя уменьшать шрифт и цели касания для имитации точного PNG.

## 6. Контракт состояния

Источники: `DeviceSnapshot`, `ReportedState`, `Freshness`, `Availability`, `PendingCommand`, `DeviceError`. UI не создаёт вторую копию истины о приборе.

| Состояние | Представление | Действия |
| --- | --- | --- |
| Загрузка без snapshot | Индикатор и нейтральная поверхность | Управление недоступно |
| Свежие данные, включено | Лавандовая поверхность и текст «Включено» | Поддерживаемые команды |
| Свежие данные, выключено | Нейтральная поверхность и «Выключено» | Поддерживаемые команды |
| Команда ожидает результата | Прогресс, прежние подтверждённые значения | Исключить повторную/конфликтующую отправку |
| Нет связи | «Нет связи», последнее состояние и время | Обновить/открыть объяснение; без ложного успеха |
| Устаревшие данные | «Данные устарели», последнее значение с временем | Актуализация перед скрытым toggle |
| Неизвестное состояние | «Состояние неизвестно» | Не считать выключенным |
| Ошибка команды | Понятное сообщение, прежнее подтверждённое значение | Повтор после устранения причины |
| Устройство удалено | Объяснение отсутствия | Вернуться к списку / перенастроить виджет |

Классификацию состояния сделать общей и тестируемой; подробность UI может различаться между экраном и виджетом. Недоступность, давность и pending — разные свойства, не один enum визуального цвета. Успех показывать только после подтверждения репозиторием; таймер браузерного демо не является подтверждением production.

## 7. Адаптация к Fold и размеру окна

Использовать фактический размер окна, системные insets и сведения о сгибе. Ориентация или название устройства сами по себе не определяют разметку. Рекомендуется Compose Material 3 Adaptive (`ListDetailPaneScaffold`) и WindowManager; выбранная политика панелей должна быть явной и покрытой проверками.

В браузере две панели включаются от 700 CSS px. **Не переносить этот порог как системную норму Android.** Стартовая нативная политика: одна панель в compact/medium, список и детали рядом в expanded, если обе панели вмещают содержимое. Сверить с прототипом на раскрытом Fold; при необходимости изменить политику scaffold с обоснованными минимальными ширинами. При крупном шрифте/малой высоте допустим переход к одной панели. Это сознательное уточнение браузерного макета.

Обязательные требования:

- В широком окне список слева, детали выбранного устройства справа; пока выбор отсутствует, справа спокойное приглашение выбрать устройство.
- Сетка в панели списка обычно двухколоночная. Если карточки не помещают название и цели касания, использовать один столбец; не масштабировать весь экран вниз.
- Переключение одной/двух панелей сохраняет выбранный `DeviceId`, черновик переименования, тему и состояние команды. Поворот не отправляет команду повторно.
- Список и детали имеют независимую прокрутку. Позиции хранить по экрану/устройству, не переносить между разными маршрутами.
- На fold/unfold и multi-window не терять доступ к Back. На compact Back из деталей ведёт к списку; на широком экране не закрывать приложение вместо возврата из вложенного действия.
- Вертикальный разделяющий сгиб учитывать по фактическим bounds/occlusion. Полоса 24 px в HTML — только иллюстрация: кнопки и текст не пересекают реальный шарнир.
- При горизонтальном сгибе/tabletop не размещать критичные действия в сгибе; выбрать доступную область либо разнести панели сверху/снизу, если хватает высоты. Одного симметричного деления 50/50 недостаточно.
- Sheet/диалог связан с активной панелью, если она достаточно широка; иначе использовать доступный modal-паттерн без обрезки действий.
- Системная IME управляется Android. Нельзя заставлять её занимать правую половину экрана по примеру HTML. Приложение адаптирует свои insets к реально показанной клавиатуре.
- Edge-to-edge, вырезы, жестовая/трёхкнопочная навигация: не применять системный отступ дважды и не помещать действия под системные панели.

Выбор и навигационные аргументы сохранять через `SavedStateHandle`/saveable-state; подтверждённые данные и команды — через репозиторий/Room. `remember` не является хранилищем состояния после смерти процесса.

## 8. Android App Widgets

### Разметка и размеры

Один экземпляр виджета связан с одним устройством; несколько экземпляров могут ссылаться на один `DeviceId`. Все получают одно подтверждённое состояние. Браузерная доска с тремя карточками — демонстрация размеров одного виджета, а не виджет со всеми устройствами.

| Вариант | Ориентир сетки | Минимальное содержимое |
| --- | --- | --- |
| Компактный | 2 × 2 | Название, состояние, давность, явные «Вкл.»/«Выкл.» |
| Широкий | 4 × 2 | Название, состояние, давность, питание; яркость при наличии места и capability |
| Расширенный | 4 × 3 | То же, поддерживаемые яркость/температура и переход в управление |

Число ячеек не задаёт одинаковый dp-размер у разных лаунчеров. Определить реальные минимальные размеры по измерению контента, включая длинное имя, pending и увеличенный шрифт. Если компактный набор не помещается, увеличить minimum resize size или изменить композицию; запрещено обрезать кнопки и состояние. Скрывать сначала дополнительные метрики, не критичные сообщения.

Фон заполняет выделенную область; не добавлять собственную внешнюю рамку-пустоту поверх launcher padding. Внутренний отступ — стартовые 16 dp. На Android 12+ использовать системный радиус виджета и согласованный внутренний радиус; на старых версиях предоставить fallback. CSS 28 px не является универсальным Android-радиусом.

Реализовать компоновки через Glance `SizeMode` и доступный `LocalSize`; конкретный режим выбрать по API закреплённой версии. При `Responsive` проверить все заявленные размеры и промежуточные окна; при `Exact` — все ветви адаптации. Не полагаться на растяжение bitmap. Метаданные минимальных/целевых размеров и resize-mode согласовать с фактически проверенными разметками.

Виджет следует системной светлой/тёмной теме рабочего стола; принудительная тема внутри приложения не должна делать виджет нечитаемым на рабочем столе. Динамические цвета использовать на поддерживаемых версиях с базовым fallback. Доступность управления не выражать одним цветом.

### Действия и жизненный цикл

- Нажатие названия открывает **детали связанного устройства**, а не просто главный экран, как упрощённая ссылка в HTML. Перед переходом проверить наличие устройства.
- «Включить» и «Выключить» отправляют явный `SetPower`, а не инверсию устаревшего кеша. Capability и права перепроверяются обработчиком.
- Во время команды показать ожидание, сохранить последнее подтверждённое состояние и предотвратить дубли. Обновлять все связанные экземпляры после результата.
- Временная надпись «только что» не должна оставаться правдоподобной часами: использовать абсолютное время подтверждения либо механизм относительного времени с гарантированным обновлением. При неопределённой свежести не утверждать актуальность.
- Нет связи, устаревание, ошибка, потеря привязки, удаление устройства, отсутствие разрешения и требование разблокировки имеют текстовое объяснение и достижимое действие восстановления.
- После рестарта процесса виджет восстанавливает привязку и данные из постоянного хранилища. Нельзя хранить единственную копию команды в callback или UI.
- Callback/worker используют общий исполнитель, дедлайн, claim и правила восстановления из раздела 7 архитектуры. Не обещать мгновенный запуск фоновой работы.
- По умолчанию не поддерживать постоянное соединение и секундный опрос только из-за наличия виджета.
- Удаление виджета удаляет привязку, а не устройство. Удаление устройства инвалидирует связанные виджеты. Restore не восстанавливает автоматически ключи Matter fabric.
- Ползунки и полноценный цветовой редактор оставить в приложении. Пресеты — отдельный этап после подтверждения capabilities и командного пути.

### Каталог и настройка

Название в каталоге: «Eluno · Устройство». Показать содержательное preview без персональных данных пользователя, поддержать fallback для старых версий Android. Превью должно соответствовать действующей разметке.

Configuration Activity получает `appWidgetId`, предлагает выбор доступного устройства и сохраняет привязку только после подтверждения. Отмена не оставляет рабочую пустую привязку. Повторная конфигурация позволяет сменить устройство. Если список пуст, дать переход к добавлению. Неподдерживаемая функция добавления виджета из приложения не должна завершаться ложным сообщением об установке.

## 9. Доступность, текст и движение

Все строки вынести в Android resources. Значения форматировать с учётом locale, единицы не вшивать в числовую модель. В demo пометка видна и озвучивается; production не содержит вымышленных «демоподтверждений».

TalkBack должен различать «Открыть устройство» и «Включить/выключить». Контролы имеют role, stateDescription и названия; выбранный цвет имеет текстовое имя, слайдер — диапазон и значение. Не объявлять одну карточку так, что вложенная кнопка теряет отдельное действие. Не дублировать подпись текстом и contentDescription без необходимости.

Минимум 48 dp для интерактивных целей, без пересекающихся расширенных областей. Проверить системный шрифт 1,0 / 1,3 / 2,0 и увеличенный display size. Не ограничивать fontScale. Фокус после закрытия диалога возвращается к инициатору; ошибки доступны экранному диктору без непрерывного переозвучивания.

Использовать стандартные анимации Material и учитывать системные настройки длительности. Прогресс не зависит только от вращения: при отключённых анимациях остаётся текст. Анимации не задерживают отправку/отмену и не служат источником состояния.

## 10. Проверки и критерии приёмки

### Матрица устройств

| Измерение | Обязательные случаи |
| --- | --- |
| Android | API 28, API 31+, текущий target SDK проекта |
| Окно | Узкое 320–360 dp, обычный телефон, широкий экран, multi-window |
| Fold | Внешний/внутренний экран, fold/unfold, вертикальный и горизонтальный сгиб |
| Высота | Альбомный режим, открытая IME, небольшой размер окна |
| Тема | Light/dark/system; dynamic on/off, разные системные палитры |
| Доступность | TalkBack, крупный шрифт, display size, анимации выключены |
| Лаунчер | Минимум два лаунчера с разной сеткой; границы resize и промежуточные размеры |
| Жизненный цикл | Поворот, recreation, process death, reboot/unlock, Doze; force stop с фиксацией ограничения ОС |

Браузерные 390×844, 840×840 и 1100×700 полезны для сравнения композиции, но не заменяют нативные проверки в dp.

### Обязательные сценарии

- [ ] Список/детали показывают одно подтверждённое значение; unknown/stale никогда не превращаются в off.
- [ ] Питание плитки не открывает детали; повторные нажатия не создают конкурирующие команды.
- [ ] Ползунок отправляет итоговый выбор, учитывает реальные границы; ошибка не подменяется успехом.
- [ ] Неподдерживаемые capability-контролы отсутствуют.
- [ ] Добавление, дубли, переименование, удаление, пустой список и ошибки имеют законченный путь.
- [ ] Темы сохраняются после перезапуска; динамическая палитра действительно системная.
- [ ] Fold/rotation/multi-window сохраняют выбор, черновик и команду без повторной отправки.
- [ ] Клавиатура, сгиб и системная навигация не скрывают действия.
- [ ] Все критичные тексты читаемы при 200% шрифте; нет горизонтального обрезания контента.
- [ ] Виджет открывает именно связанное устройство; конфигурация и отмена корректны.
- [ ] Несколько виджетов одного устройства синхронизируются после подтверждения.
- [ ] Нет связи, удаление устройства, reboot/restore и отсутствие разрешения не оставляют ложные активные кнопки.
- [ ] Производственная сборка не выдаёт fake-результаты за Matter.

Проверки состояния и маппинга покрыть unit-тестами, пользовательские действия и семантику — Compose UI/instrumentation. Для виджетов дополнить тестами callback/привязок и ручной проверкой в лаунчере. Выполнить существующие проверки проекта, затронутые изменениями. Не считать screenshot-тест доказательством корректной команды.

Визуальная приёмка: одинаковые данные, тема, fontScale, размер области контента; источник и Android-снимок рядом. Сравнивать иерархию, сетку, переносы, отступы, цветовые роли и состояния. Разницу системных панелей не считать ошибкой дизайна. Сохранять снимки и список устройств/API вместе с результатами. Блокирующие дефекты: недоступное действие, обрезанный текст состояния, перекрытие сгибом/IME, ложное подтверждение, потеря состояния. Непроверенные устройства явно перечислять.

## 11. Порядок реализации и передача

1. Выделить тему/токены и маппинг состояния без изменения семантики команд.
2. Перенести список и карточки; проверить компактный экран и TalkBack.
3. Перенести детали, добавление, настройки и диалоги; проверить ошибки и IME.
4. Ввести адаптивную навигацию и реальные сведения о сгибе; пройти матрицу окон.
5. Реализовать Glance, конфигурацию и устойчивое обновление через общий командный путь.
6. Выполнить визуальную и функциональную приёмку, обновить [контекст](../CONTEXT.md) и ограничения.

Готовность этапа подтверждается работающей Android-сборкой, проверками и сохранёнными доказательствами. HTML-макет и этот документ сами по себе не означают готовности нативного приложения.
