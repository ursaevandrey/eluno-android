# Matter: подключение и управление

Дата: 31 октября 2026 года.

## Реализация

Приложение использует `AndroidMatter`. Деморежим, демонстрационные устройства и product flavors удалены. Обычные `debug` и `release` используют реальный Matter. Новая установка начинает с пустого каталога; устройство появляется после подключения. Тестовые реализации транспорта существуют только в `src/test` и не входят в APK.

- Подключение по ручному коду Matter, вставленному тексту QR (`MT:`) или встроенному сканеру. Кнопка «Сканировать QR-код» запрашивает CAMERA только при нажатии. Распознавание локальное, без отправки изображения и сохранения снимков; используется [ZXing Android Embedded 4.3.0](https://github.com/journeyapps/zxing-android-embedded/tree/v4.3.0). После сканирования код попадает в форму, подключение запускается отдельной кнопкой. Посторонние QR отклоняются; полную проверку Matter payload выполняет SDK до pairing. Камера освобождается при уходе в фон, возврате и успешном сканировании. Ручной ввод доступен при отказе в разрешении или ошибке камеры.
- Добавление запускается только по QR или вручную введённому коду. Отдельный поиск и перечисление устройств в локальной сети удалены из UI, ViewModel, repository и Matter port. Разрешение адреса заданного устройства и PASE остаются частью подключения через SDK.
- Собственная fabric, полная проверка attestation с production PAA из закреплённого SDK. Проверка не отключается, тестовые PAA не добавляются. Онлайн-проверка отзыва сертификатов SDK здесь не реализована.
- Wi-Fi provisioning через BLE либо подключение уже находящегося в локальной сети Wi-Fi/Ethernet-устройства. Thread-only и ICD отклоняются. Для multi-admin нужен код открытого commissioning window от существующего администратора.
- Descriptor discovery по endpoints, ServerList, DeviceTypeList и FeatureMap. Возможности OnOff, Level, Hue/Saturation и ColorTemperature назначаются по результатам чтения, а не по категории. Для температуры учитываются физические пределы в mireds. XY-only color не объявляется как поддерживаемый RGB control.
- Команды On/Off, MoveToLevel, MoveToHueAndSaturation, MoveToColorTemperature. Ответ Invoke сам по себе не подтверждает состояние: после него читаются атрибуты и сравниваются с целью с учётом округления протокола. Автоматического повтора Invoke нет.
- Подписки на фактические атрибуты; частичные отчёты объединяются. Сохраняются подтверждённые значения, pending и ошибка отдельно. При потере связи старые значения остаются stale, неизвестные не становятся `off`.
- Повторное чтение/подписка с задержкой 1–30 секунд и jitter, периодическое чтение каждые 15 секунд в активном приложении (следующий интервал после завершения ответа, тайм-аут 25 секунд), новая CASE-сессия после потери/смены сети. Интернет и признак Android VALIDATED не требуются.
- Единый контроллер и общий наблюдатель сети в процессе. Подписки привязаны к каталогу и переднему плану приложения, а не к числу UI collectors. После двух секунд в фоне подписки освобождаются.
- JNI device pointers освобождаются, поздние callbacks после отмены игнорируются или освобождают полученный ресурс. Для установленной подписки отменяется её ID. Пока ID ещё не получен, SDK допускает только отмену на уровне узла; подписки соседних endpoints в этом случае восстанавливаются общим retry-путём.

## Сохранение и восстановление

`FabricStore` шифрует KVS SDK AES-GCM с ключом Android Keystore; операции записи синхронны. Fabric ID и случайный 16-байтовый IPK переживают перезапуск. Android backup отключён. Код подключения и пароль Wi-Fi не записываются в Room, SavedState или журнал.

Room schema v4 не хранит незавершённые попытки подключения. Таблица commissioning удаляется миграцией 3→4; API восстановления и список попыток удалены. NodeId текущей попытки находится только в памяти. Устройство и его endpoints сохраняются одной транзакцией только после успешного inspection. При запуске приложения и открытии Add старые попытки не продолжаются. Ключи fabric и автоматическое восстановление связи с уже добавленными устройствами сохранены.

Управляемый endpoint получает стабильный ID `matter-<nodeHex>-<endpoint>`. Отображаемое имя берётся из формы без автоматического добавления точки и номера endpoint. Повторная инспекция не создаёт дублей и не затирает пользовательское имя. NodeId не преобразуется в signed десятичный идентификатор хранилища.

Записи Running и pending сохраняются транзакционно. После гибели процесса pending снимается с результатом Interrupted, кэш становится stale/unknown. Команда не отправляется повторно. При отмене активной coroutine применяется та же семантика; устройство могло уже выполнить команду, поэтому дальнейшее чтение необходимо.

Полная очередь команд с lease/WorkManager из целевой архитектуры, фоновые виджеты и удаление fabric с устройства в эту реализацию не входят.

Миграция 2→3 удаляет только прежние синтетические устройства (с `templateId` или ID `demo-*`), их snapshots, команды и привязки виджетов. Из таблицы устройств удалён `templateId`. Реальные устройства, журнал commissioning и настройки сохраняются; миграция доступна и из v1 через v2. Старый demo APK имел отдельный application ID: новый APK не обновляет и не удаляет его автоматически с телефона.

## Закреплённый SDK и сборка

- Репозиторий: [project-chip/connectedhomeip](https://github.com/project-chip/connectedhomeip).
- Release: [v1.6.1.0](https://github.com/project-chip/connectedhomeip/releases/tag/v1.6.1.0).
- Commit: `3bcdd56ba54fb88b2afb4bfef575014671df7aa7`.
- NDK: `28.2.13676358`, ABI: `arm64-v8a`.
- 75 production PAA из `credentials/production/paa-root-certs` этой версии.
- Java/Kotlin bindings собираются в `:core:chip` из того же checkout, что и JNI. Неиспользуемые дубли BatchInvoke и callback для SDK-тестов исключены из Java compilation.
- `patches/connectedhomeip-eluno.patch` заменяет тестовый IPK в Android issuer на IPK Eluno и открывает два существующих C++ API через JNI: остановку commissionable discovery и пометку старых CASE-сессий как defunct. Полный DAC verifier сохраняется.
- Native logging отключён при сборке. JNI-классы сохраняются правилами R8.

Из `eluno-android-app`:

```sh
./scripts/build-matter-sdk.sh
./gradlew test assembleDebug lintDebug
python3 scripts/verify-schema-migration.py
```

Для SDK нужны Git, Python 3, JDK 17, установленный Android SDK и NDK указанной версии. Скрипт использует `ANDROID_HOME`, иначе стандартный путь macOS. Первый запуск скачивает SDK, Android submodules и инструменты Pigweed через официальный bootstrap; это большой локальный build cache. Каталоги `.matter-sdk` и `.sdk-reference` исключены из Git.

Скрипт проверяет commit и применённый патч, записывает SHA-256 патча и native-библиотек. Gradle проверяет маркер версии, соответствие патча и наличие JNI/PAA перед сборкой модуля. Production APK включает только ARM64; для другого ABI нужен отдельный согласованный SDK build.

По умолчанию controller vendor ID — тестовый `0xFFF4`, пригодный для разработки. Для выпуска продукта требуется собственный выданный vendor ID, передаваемый десятичным числом через `-PmatterVendorId=...`.

## Форма добавления

Поле названия расположено первым. Основной способ ввода — кнопка «Сканировать QR-код»; ссылка «ввести вручную» заменяет её полем «Код Metter» и ссылкой «Сканировать QR» для возврата. Переключение режима не очищает введённое название или код. Кнопка «Ввести код вручную» в камере сразу возвращает форму с открытым полем кода. Подпись настройки сети и switch выровнены по вертикальному центру. Открытие формы не запускает поиск или подключение.

## Разрешения Android

При включении настройки Wi-Fi автоматически подставляется SSID текущего подключения телефона; ручной ввод и повторная подстановка остаются доступны. Пароль сети Android приложению не передаёт, он вводится вручную. При изменении SSID введённый пароль очищается. Используется одноразовое чтение `WifiManager.connectionInfo` (поддерживается и после API 31, также при активном VPN), без сканирования соседних сетей. Для SSID нужны точное местоположение и включённая геолокация; FINE/COARSE_LOCATION запрашиваются совместно при попытке автоподстановки. Отказ не блокирует ручной ввод, открываются настройки доступа/геолокации. Основание: [WifiManager](https://developer.android.com/reference/android/net/wifi/WifiManager#getConnectionInfo()) и [запрос разрешений местоположения](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime).

Wi-Fi provisioning запрашивает Bluetooth Scan/Connect на Android 12+ и location на Android 9–11. Состояние Bluetooth и системной геолокации проверяется до запуска BLE. На Android 17 приложение запрашивает доступ к локальной сети, с обработкой отказа и переходом к настройкам. Основание: [Android Local network permission](https://developer.android.com/privacy-and-security/local-network-permission).

Автоматические тесты проверяют оркестрацию на управляемом транспорте, а не радиоканал/JNI на телефоне. Для аппаратной приёмки ещё нужно:

1. Запустить production APK на разрешённом ARM64-телефоне; проверить разрешения и отказ в них.
2. Подключить сертифицированное Wi-Fi-устройство с заводского состояния через BLE и устройство с открытым multi-admin window через LAN.
3. Проверить все заявленные команды, изменение состояния другим администратором, многоканальный endpoint и отключение питания устройства.
4. Переключить Wi-Fi/выключить роутер и убедиться в восстановлении подписки без повторной команды.
5. Перезапустить процесс во время команды или добавления; незавершённая попытка добавления не должна сохраняться или продолжаться автоматически. Повторное явное добавление с новым кодом должно корректно использовать уже существующий доступ при 126.
6. Проверить, что недоверенный attestation и Thread-only устройство отклоняются.

31.10.2026 обновлённый APK установлен на Galaxy Note9 с сохранением данных. Проверены запуск, кнопка сканирования, отказ/разрешение CAMERA, открытие задней камеры и возврат в форму; после выхода камера освобождается, падений нет. Распознавание физической наклейки и подключение Matter-устройства ещё не проверены. Эмулятор Android в текущем SDK не установлен. Нативная сборка и упаковка не заменяют аппаратную приёмку.

## QR с тёмного экрана другого контроллера

Сканер использует MixedDecoder для двух полярностей. Для обычного QR без светлого свободного поля на тёмном фоне добавлен ограниченный fallback: выделение кандидата, восстановление окружения и выравнивание небольшого наклона. Дополнительная обработка выполняется после неудачи основного чтения не чаще одного раза на три таких кадра. Присланный скриншот не распознавался старым декодером и успешно читается новым; тест использует production factory. Регрессия запускается с `ELUNO_QR_TEST_IMAGE=/absolute/path/to/image` перед Gradle; изображение не включается в проект и значения кодов не выводятся. Без переменной пропускается только эта локальная проверка, остальные тесты используют синтетические изображения с публичным тестовым payload. Gradle отслеживает наличие и изменение локального входного файла. На Note9 проверены запуск обновлённого сканера и освобождение камеры после выхода; оптическое считывание с другого экрана не выполнялось.

## Завершение попытки подключения

После успешного onCommissioningComplete приложение не вызывает StopPairing повторно: SDK уже завершил процедуру. При ошибке/тайм-ауте/отмене остановка остаётся, а возможный сбой очистки не заменяет исходный результат. Completion listener освобождается даже при ошибке остановки. Это исправляет показ ложного `Invalid device descriptor (0x33)` из CHIPDeviceController.cpp:1202 и потерю исходной ошибки. На Note9 наблюдалась именно эта вторичная ошибка; по ней нельзя определить фактический исход сопряжения. Исправление покрыто четырьмя тестами и установлено, реальная повторная попытка ещё не выполнялась.

## Уже существующий доступ Eluno (126)

126 = CHIP_ERROR_FABRIC_EXISTS. Через расширение JNI SDK запрашивает Fabrics при commissioning и ищет совпадение одновременно fabric ID и root public key. Новый getMatchingFabricNodeId возвращает найденный operational NodeId. При onCommissioningComplete с кодом 126 и ненулевым совпадением Eluno использует его для обычного CASE/Descriptor inspection, после чего сохраняет готовое устройство. Без совпадения или при любой другой ошибке такой переход запрещён. Исходная attestation не обходится. Восстановление не использует журнал попыток; другой контроллер и его fabric не удаляются. Патч JNI пересобран для ARM64, путь покрыт тестами выбора NodeId и сохранения каталога; реальное повторное добавление ещё требует проверки пользователем с новым кодом.
